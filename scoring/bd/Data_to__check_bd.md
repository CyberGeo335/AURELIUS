# AURELIUS — README: данные для проверки комплектности кредитной заявки

**Назначение:** справочник для модуля проверки наличия обязательных сведений в заявках R01, R02 и R03. Документ показывает, где искать значения, что означают поля, откуда они потенциально поступают и как использовать их при проверке. Указанные внешние источники — предполагаемые интеграции, а не подтверждённые действующие подключения.

## 1. Общий принцип

1. По `credit_applications.application_id` определить `company_id` и `product_code`.
2. По `companies.company_id` получить `entity_type` (`LEGAL_ENTITY` или `INDIVIDUAL_ENTREPRENEUR`).
3. Из `application_field_requirements` выбрать правила для продукта; обязательность определяется `required_ooo` / `required_ip`.
4. По `field_code` и `target_db_field` проверить уже сохранённые значения в `application_field_values` и типизированных таблицах ниже. `target_db_field` — описание назначения поля, **не исполняемый SQL**: нужен явный маппинг в коде.
5. Проверить не только непустое значение, но и формат, актуальность, подтверждение и непротиворечивость.
6. При отсутствии обязательного значения сформировать запрос в `application_data_requests`; ответы сохранять в соответствующие типизированные поля и в `application_field_values` с указанием происхождения.
7. Обновить `credit_applications.missing_data_status`: `COMPLETE`, `PARTIAL` или `CRITICAL_MISSING`. `COMPLETE` не означает автоматического одобрения.

В справочнике анкеты сейчас 99 строк требований: **R01 — 31, R02 — 34, R03 — 34**. Не все 99 полей обязательны для каждого заявителя.

## 2. `companies` — сведения о компании или ИП

**Для чего:** регистрационные данные, характеристики деятельности, тип заёмщика. **Предполагаемые источники:** ЕГРЮЛ/ЕГРИП ФНС, Единый реестр МСП, клиент, CRM банка.

| Колонка PostgreSQL | Что означает | Предполагаемый источник |
|---|---|---|
| `company_id` | Идентификатор компании в БД | AURELIUS |
| `entity_type` | Тип заявителя: юридическое лицо / ИП | Анкета, проверка по ЕГРЮЛ/ЕГРИП |
| `inn` | ИНН — идентификационный номер налогоплательщика | ЕГРЮЛ/ЕГРИП |
| `ogrn` | ОГРН — основной государственный регистрационный номер юрлица | ЕГРЮЛ |
| `ogrnip` | ОГРНИП — основной государственный регистрационный номер ИП | ЕГРИП |
| `name` | Наименование организации или Ф. И. О. ИП | ЕГРЮЛ/ЕГРИП |
| `kpp` | КПП — код причины постановки на учёт (для юрлиц) | ЕГРЮЛ |
| `legal_form` | Организационно-правовая форма (например, ООО) | ЕГРЮЛ |
| `registration_date` | Дата государственной регистрации | ЕГРЮЛ/ЕГРИП |
| `status` | Статус деятельности (например, действующая, ликвидируется) | ЕГРЮЛ/ЕГРИП; нормализация системой |
| `status_date` | Дата действия указанного статуса | ЕГРЮЛ/ЕГРИП |
| `okved_main` | Код основного вида деятельности по ОКВЭД | ЕГРЮЛ/ЕГРИП |
| `okved_main_name` | Наименование основного вида деятельности | ЕГРЮЛ/ЕГРИП, справочник ОКВЭД |
| `legal_address` | Юридический адрес | ЕГРЮЛ |
| `actual_business_address` | Фактический адрес ведения бизнеса | Клиент / CRM |
| `actual_activity_description` | Описание фактической деятельности | Клиент / CRM |
| `actual_activity_start_date` | Дата фактического начала деятельности | Клиент |
| `business_region` | Регион ведения бизнеса | Клиент / CRM |
| `business_city` | Город ведения бизнеса | Клиент / CRM |
| `sme_category` | Категория субъекта МСП | Единый реестр МСП ФНС |
| `director_name` | Ф. И. О. руководителя юрлица | ЕГРЮЛ |
| `director_position` | Должность руководителя | ЕГРЮЛ |

## 3. `credit_applications` — параметры заявки

**Для чего:** идентификация заявки, выбранного продукта и запрошенных условий. **Источник:** клиент / интерфейс подачи заявки; служебные статусы — AURELIUS.

| Колонка PostgreSQL | Что означает | Источник |
|---|---|---|
| `application_id` | Идентификатор заявки | AURELIUS |
| `company_id` | Компания-заявитель | Связь с `companies` |
| `product_code` | Код продукта: `R01`, `R02`, `R03` | Выбор клиента |
| `purpose` | Цель кредитования | Клиент |
| `requested_amount` | Запрошенная сумма кредита или лимита, ₽ | Клиент |
| `requested_term_days` | Запрошенный срок в днях | Клиент / интерфейс |
| `requested_term_months` | Запрошенный срок в месяцах | Клиент / интерфейс |
| `application_status` | Статус обработки заявки | AURELIUS |
| `missing_data_status` | Статус комплектности данных | Модуль проверки AURELIUS |

Для R02/R03 **срок договора не равен сроку транша**. Не следует автоматически трактовать `requested_term_days` как срок транша.

## 4. `application_details` — контакт, поручительство и подтверждение

**Для чего:** сведения о представителе, подписанте, поручительстве и подтверждении анкеты. **Источники:** клиент, CRM, документы о полномочиях, системный журнал.

| Колонка PostgreSQL | Что означает | Источник |
|---|---|---|
| `application_id` | Идентификатор заявки | Связь с `credit_applications` |
| `guarantor_participation` | Участвует ли поручитель | Клиент / условия банка |
| `proposed_collateral` | Предлагается ли залог | Клиент |
| `contact_full_name` | Ф. И. О. контактного лица | Клиент / CRM |
| `contact_role` | Роль контактного лица (ИП, руководитель, представитель) | Клиент / CRM |
| `contact_phone` | Телефон контактного лица | Клиент / CRM |
| `signer_full_name` | Ф. И. О. подписанта | Клиент / документы |
| `signer_authority_basis` | Основание полномочий подписанта | Клиент / документы |
| `confirmation_version` | Версия подтверждённых сведений | AURELIUS |
| `confirmed_at` | Время подтверждения заявки | AURELIUS |

`guarantor_participation = FALSE` означает лишь отсутствие заявленного поручителя, но не отсутствие возможного требования банка.

## 5. `application_product_details` — особенности R02/R03

**Для чего:** параметры кредитной линии, траншей, периода выборки и счёта овердрафта. **Источники:** клиент, продуктовые условия, АБС банка.

| Колонка PostgreSQL | Что означает | Применение |
|---|---|---|
| `application_id` | Идентификатор заявки | Все продукты |
| `company_id` | Компания-заёмщик | Все продукты |
| `max_tranche_term_value` | Числовое значение предельного срока транша | R02/R03 |
| `max_tranche_term_unit` | Единица срока: `DAYS` или `MONTHS` | R02/R03 |
| `drawdown_start_date` | Начало периода доступности выборки | R02 |
| `drawdown_end_date` | Конец периода доступности выборки | R02 |
| `drawdown_period_months` | Продолжительность периода выборки, мес. | R02 |
| `is_revolving` | Возобновляется ли доступный лимит после погашения | R02/R03 |
| `overdraft_bank_account_id` | Идентификатор счёта из `company_bank_accounts` | R03 |
| `overdraft_account_ref` | Номер расчётного счёта овердрафта | R03 |
| `overdraft_bank_name` | Название банка счёта | R03 |
| `overdraft_bank_bik` | БИК банка (9 цифр) | R03 |

Пример: `max_tranche_term_value = 6`, `max_tranche_term_unit = 'MONTHS'` означает 6 месяцев; `60` и `DAYS` — 60 дней. Срок и единицу всегда проверять вместе.

## 6. `company_contacts` — контакты из профиля компании

**Для чего:** автозаполнение контактных сведений при наличии данных в банковском профиле. **Источники:** CRM, предыдущие анкеты, клиент.

| Сведения | Что означают | Куда использовать |
|---|---|---|
| Идентификатор компании | Привязка контакта к заёмщику | Поиск контактов компании |
| Ф. И. О. | Контактное лицо | `application_details.contact_full_name` |
| Роль / должность | Положение контактного лица | `application_details.contact_role` |
| Телефон | Номер связи | `application_details.contact_phone` |
| Электронная почта | Адрес для связи, если имеется | Использовать согласно правилам приложения |
| Актуальность | Когда и как контакт подтверждён | Проверка достоверности |

**Примечание:** здесь приведены смысловые атрибуты, **не подтверждённые точные имена колонок** таблицы `company_contacts`. Для SQL-мэппинга нужно использовать реальные имена из схемы.

## 7. `company_bank_accounts` — банковские счета

**Для чего:** проверка реквизитов, выбор счёта для R03. **Источники:** АБС банка, реквизиты клиента; БИК сверяется со справочником Банка России.

| Сведения | Что означают | Куда использовать |
|---|---|---|
| Идентификатор счёта | Ключ банковского счёта в AURELIUS | `application_product_details.overdraft_bank_account_id` |
| Идентификатор компании | Владелец счёта | Проверка соответствия компании в заявке |
| Номер счёта | Расчётный счёт | `application_product_details.overdraft_account_ref` |
| Название банка | Банк открытия счёта | `application_product_details.overdraft_bank_name` |
| БИК | Банковский идентификационный код | `application_product_details.overdraft_bank_bik` |
| Статус счёта | Действует ли счёт, если известно | Проверка применимости для R03 |
| Дата проверки | Актуальность сведений | Проверка свежести |

**Примечание:** таблица содержит эти категории сведений по назначению, но точные SQL-имена всех полей здесь не заявляются без сверки со схемой. Составной FK `(overdraft_bank_account_id, company_id)` запрещает привязку счёта другой компании.

## 8. Как модуль определяет результат проверки

| Состояние поля | Действие |
|---|---|
| Значение есть и корректно | Учитывать как заполненное, отдельно проверять подтверждение |
| Значение отсутствует | Создать запрос недостающего сведения |
| Неверный формат | Попросить исправление |
| Источники противоречат друг другу | Отметить конфликт, запросить подтверждение |
| Сведения устарели | Запросить обновление |

**Основные таблицы для чтения:** `credit_applications`, `companies`, `application_field_requirements`, `application_field_values`, `application_details`, `application_product_details`, `company_contacts`, `company_bank_accounts`.

**Основные таблицы для записи:** `application_field_values` (значение и источник), типизированные таблицы (соответствующие поля), `application_data_requests` (запросы недостающих данных), `credit_applications.missing_data_status` (итоговый статус). Проверки качества могут фиксироваться в `data_quality_checks`.

**Граница модуля:** проверка комплектности не вычисляет PD и не принимает кредитное решение. Скоринг и Decision Engine — отдельные этапы.
