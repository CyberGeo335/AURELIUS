# Версия БД v4 — актуальная

Полный эталонный снимок `business_scoring` от 26.10.2026 на основе v3.
В `public.bank_transactions` добавлены 60 синтетических операций выручки:
по одной за сентябрь и октябрь 2025 года для каждой из 30 DEMO-компаний.

- `direction='IN'`, `operation_category='REVENUE'`, `currency='RUB'`.
- Сумма каждой операции — 1 200 000,00 ₽, как в существующем ноябре 2025.
- Даты операций — 15.09.2025 и 15.10.2025, 00:00 UTC.
- `payment_purpose` и `source_statement_id` явно обозначают синтетическое
  дополнение; `source_checked_at` содержит время добавления, а не заднюю дату.
- Всего в таблице 780 строк; прежние 720 операций и данные остальных
  34 таблиц сохранены без изменений. Структура БД не менялась.

Файлы:

- `business_scoring_wauth.backup` — полный custom-format pg_dump, включая
  `user_accounts`, последовательности, ограничения и триггеры.
- `schema_actual.sql` — структура той же версии.
- `manifest.json` — SHA256 файлов, числа строк и результаты проверок.

Дамп подготовлен в изолированной БД из v3 без параллельных записей.
Архив полностью восстановлен во вторую временную PostgreSQL-базу:
числа строк и SHA256 отсортированных JSON-строк совпали во всех 35 таблицах.
Проверены все 60 пар «компания — месяц», неизменность исходных операций
и повторный запуск дополнения без новых вставок.

Для существующего DEMO использовать только добавочный скрипт:

```sh
psql -v ON_ERROR_STOP=1 -d business_scoring -f scoring/bd/seeds/backfill_revenue_2025_09_10.sql
```

Скрипт определяет 30 DEMO-компаний по существующим синтетическим банковским
реквизитам. При другом числе компаний/счетов транзакция отменяется.
Уже имеющаяся положительная выручка в RUB за нужный месяц пропускается.
Скрипт не запускается автоматически при старте приложения.

Полный backup восстанавливать только в новую пустую БД:

```sh
pg_restore --no-owner --no-privileges --exit-on-error -d NEW_DATABASE "scoring/bd/v_4 (actual)/business_scoring_wauth.backup"
```

Предыдущий снимок сохранён в `scoring/bd/v_3`. Пароли ролей PostgreSQL и
настройки кластера не входят в pg_dump базы. Данные DEMO синтетические.
