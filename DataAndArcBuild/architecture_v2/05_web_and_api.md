# V2 · WEB и версионный API

## Реализованный HTTP-контракт ядра

| Метод / путь | Результат |
| --- | --- |
| GET `/api/v2/health` | api_version, DEMO, capabilities; не имитирует probe доступности модели/PG |
| GET `/api/v2/cases` | Кейсы доверенного владельца и компании |
| GET `/api/v2/cases/{case_id}` | View, версия, запрос, pending, история и доступные действия |
| POST `/api/v2/commands` | CREATE/CHAT/CONFIRM_FACTS/UPDATE_REQUEST/SELECT_PRODUCT/CANCEL и зарезервированные M3–M5-команды |

POST использует `Command`; ответ — `View`. Схемы доступны из Pydantic `model_json_schema()`. Неизвестные поля отвергаются. `case_id + expected_version` обязательны для существующего кейса. Размер JSON ограничен 64000 байт; файлы через этот endpoint не загружаются.

Локальный gateway слушает loopback :5180, проверяет Host/Origin и bearer token из `AURELIUS_V2_API_TOKEN` (не менее 32 символов). Токен сопоставлен одному серверному профилю из CLI. Cookie, существующий V1 login и клиентские пароли не переиспользуются автоматически. Токен не следует встраивать в Vite bundle, URL или localStorage. Доступ через браузер потребует согласованной серверной сессии/BFF; текущий gateway предназначен для локального API-клиента и проверок.

Ошибки: 400 — неверная команда; 401 — нет gateway-токена; 403 — origin/доступ; 409 — version/receipt/stage conflict; 503 — не удалось подтвердить исполнение. SERVICE_NOT_CONFIGURED и другие доменные ожидания находятся в `View.error_code` при сохранённом ходе. Повторяется только исходная команда с прежним ID; исправленное содержимое получает новый ID.

## Что изменить в WEB следующим этапом

1. Явно внедрять HttpAuthApi/HttpCreditApi/HttpChatApi V2 вместо mock. Не переключаться на mock при сбое backend.
2. Использовать серверные owner/company/borrower вместо karpov/zerno; клиентские названия и реквизиты брать из разрешённого профиля.
3. Привязать маршрут страницы и диалог к `case_id`, GET состояния — при входе/переключении. Pending/history восстанавливаются с сервера; локальный кэш изолирован по личности/кейсу.
4. CHAT показывает `pending` с цитатами. «Да, верно» отправляет CONFIRM_FACTS; правка формы — UPDATE_REQUEST. Локальный applyAssistant не создаёт вторую заявку.
5. Разделить `version` для конкурентных команд и `revision` для финансовых результатов; на 409 перечитывать состояние и не переписывать изменённую чужой вкладкой форму молча.
6. Визуальные статусы — проекция ответа backend. `tick()` может обновлять чтение, но не генерировать решение. allowed_actions помогает UI, проверки остаются серверными.
7. Отдельно подключить consent registry, документы/анкету, бизнес-порты и операторский контур; временно скрывать недоступные действия по capabilities.
8. Отдельно показывать «модель недоступна», «справочник недоступен», «данные ещё не загружены», «модель неприменима», «требуется инженерная интеграция».

V2-core не реализует CreditApi WEB один к одному: createDraft/saveDraft/submit, document requests и sign/fund имеют разные бизнес-контракты. Их маппинг должен учитывать отсутствие подключённых сервисов и действительный продуктовый смысл.

В рамках начального пакета `personalCab/web`, nginx/Docker/Compose и V1 server не меняются. Работающий UI :5175 по-прежнему mock. Общий origin, auth и маршрутизация будут отдельной интеграцией с регрессией V1.
