# V2 · решения, трассируемость и этапы

> Актуальное продолжение: [интегрированный V2 DEMO](../../docs/V2_INTEGRATED_DEMO.md). Серверный вход, WEB и бизнес-адаптеры M3–M5 подключены. Ниже сохранено описание этапа ядра 0.1.

## Принятые для новой ветви решения

| ADR | Решение | Основание |
| --- | --- | --- |
| V2-001 | V1 сохраняется; отдельные пакет, схема и API | Прямой запрос пользователя 25.10.2026 |
| V2-002 | RAG сохраняется read-only, без LLM для справки | Запрос пользователя и уже проверенный контур источников |
| V2-003 | Новый LangGraph orchestration и явный адрес команды | AST-08, конкурентная работа вкладок, сверка архитектуры |
| V2-004 | Чат предлагает, CONFIRM_FACTS применяет; форма работает без LLM | AST-02, AST-04 и единый серверный кейс |
| V2-005 | Проверенные примитивы переиспользуются через адаптеры | Не копировать весь V1 workflow и не ослаблять валидацию/RAG |
| V2-006 | M3–M5 подключаются отдельными проверенными адаптерами | Нет неявного запуска V1 или фиктивных результатов |
| V2-007 | Автоодобрение и новые финансовые пороги не вводятся | В запросе нет изменения согласованной методологии; UI-мок её не утверждает |

Эти решения задают начальный технический вариант V2. Финансовые изменения и спорные правила требуют отдельного решения пользователя; новая папка архитектуры сама по себе не утверждает кредитную policy.

## Состояние реализации 0.1

**Реализовано:** отдельный граф; типизированные команды и View; version/revision; ownership; create/list/state/cancel; общий request формы/чата; proposals; строгие поля и цитаты; один repair в адаптере LLM; вопросы и DataResolutionPlan; каталог 16 направлений; read-only RAG; MemoryRepository только явно; PostgreSQL repository и отдельный SQL bootstrap; локальный token gateway; доменные, HTTP и opt-in PG тесты.

**Переиспользуется:** схемы значений/диагностики, библиотечные проверки извлечения и merge repair, prompt/schema базовых ограничений, каталог/матчер, RAG/index/source, конфигурация подключения PostgreSQL. Из старого WorkflowApp, ChatService и case repository ничего не вызывается.

**Не подключено:** WEB V2 к новому API; пользовательский IAM/consent registry; verified legal_form lookup; бизнес-анкета/документы/snapshot; реальный M4/M5; объяснения модели и operator API; deployment V2. Полноценная изоляция бизнес-результатов `public` должна быть спроектирована до подключения M3–M5.

Это работающая первая реализация нового диалогового ядра, а не заявление о завершённой миграции пяти бизнес-модулей.

## Следующие этапы и критерии

1. **Клиентская интеграция:** доверенный session adapter и V2 HttpCreditApi; чат/форма/список показывают один case/version после reload и в двух вкладках.
2. **Согласия и M3:** долговечные grants/revocations, scoped файлы/анкета, cutoff/provenance/snapshot; клиент не верифицирует себя; данные переживают перезапуск.
3. **M4:** V2 registry/feature inputs, проверенные mapping, реальные результаты с null/unsupported и правильным kind/horizon; отдельная регрессия модели.
4. **M5 и банк:** отдельная operator identity/права, scoped решения и offers, expiry/revision/idempotency, R01 vs R02/R03. Неполные досье не превращаются в отказ автоматически.
5. **Доставка:** единый origin и auth, сборка WEB, изолированные ресурсы, явный маршрут отката к V1. Рабочие тома и кейсы не перезаписываются.

## Проверки

Основные автоматические проверки нового пакета — `personalCab/prom_v2/tests`. HTTP требует loopback. PG-тест запускается только при AURELIUS_TEST_DATABASE_URL на выделенную seeded DB, создаёт записи с уникальным тестовым владельцем и не чистит чужие таблицы. Live-модель проверяется отдельно; отсутствие live-прогона нельзя заменить тестом с подставленным Extractor.

Фактические результаты текущего запуска фиксируются в [VALIDATION.md](../../personalCab/prom_v2/VALIDATION.md). Полный runtime V1 должен проходить собственную регрессию, так как новые адаптеры используют общие примитивы, хотя старые файлы не меняются.
