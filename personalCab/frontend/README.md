# AURELIUS — единый кабинет и модули 1–5 DEMO

Кабинет использует тот же серверный кейс, что чат. PostgreSQL хранит заявки, сессии, согласия, анкеты, файлы, снимки, оценки и ручные решения; localStorage больше не является источником заявок. Предыдущие локальные данные не удаляются и не импортируются автоматически.

[Актуальный запуск, сценарии и операторские команды](../../docs/DEMO_MODULES_1_5.md). [Архитектурная карта](../../DataAndArcBuild/architecture/00_architecture_overview.md).

## Запуск

```sh
/Users/retro0/projects/PyVenv/venv_core/bin/python -m personalCab.prom.prom_lab.ai_agents_lab.database --init-workflow
/Users/retro0/projects/PyVenv/venv_core/bin/python -m personalCab.frontend.server --company-id 40 --allowed-company-ids 40
```

Либо `docker compose up --build -d`. Открыть http://127.0.0.1:5173/. Ollama с `gpt-oss:20b` запускается отдельно. Настройки БД — `PG_*`/pgpass или `AURELIUS_DATABASE_URL`; Python сам не загружает `.env`. `--database PATH` — явно выбранный legacy/test режим М1–М2.

## Поведение кабинета

- Чат извлекает подтверждённые текущим текстом изменения; типизированные команды формы работают без LLM. Ревизии и неизвестные значения сохраняются.
- «Мои заявки», форма и чат показывают одни кейсы; закрытые кейсы сохраняются. Новая сессия доступна после завершения/отмены.
- В «Компания, согласия и действия DEMO» выбирается оператором разрешённый субъект, выдаются/отзываются отдельные часовые согласия, запускаются обновление данных, оценка и подача.
- Адресная анкета сохраняет ответы как CLIENT/UNVERIFIED. Проверка оператором не подменяется сообщением клиента. CSV/XLSX/PDF-текст извлекаются как непроверенные данные; сканы требуют ручной проверки.
- М4 загружает настоящий CatBoost по registry/SHA-256. Входы должны быть явно проверены оператором; без них результат INSUFFICIENT_DATA и вероятность null.
- М5 получает ручное решение и предложение через доверенный CLI. Принятие, симуляция исполнения и платежей подтверждаются отдельно; реальных переводов и юридических подписей нет.

В логе видны case/revision/status, адресные замечания, продукты/требования, ссылки snapshot/recheck, точный вид оценки и результат ручного рассмотрения. Полные финансовые строки и бинарные документы не возвращаются в общий лог. Контракты API и ограничения приведены в связанном руководстве.

## Проверка

```sh
/Users/retro0/projects/PyVenv/venv_core/bin/python -m pytest personalCab/frontend/tests personalCab/prom/prom_lab/ai_agents_lab/tests -q
```

HTTP-тесты используют локальные порты, PostgreSQL-тесты требуют отдельной seeded БД через `AURELIUS_TEST_DATABASE_URL`. Локальный DEMO-контур не является production IAM или банковским API.

## Справочные вопросы по требованиям

Чат поддерживает [RAG требований](../prom/rag/README.md) через FAISS и LangGraph. Примеры: «Какой формат ИНН для R01 ООО?» и «Какие требования к заявке R02 для ИП?». Ответ содержит коды полей и ссылки на записи JSON; версия и структурированные цитаты доступны в `result.knowledge_answer` и `workflow_log.knowledge_answer`. Для этой ветки Ollama не требуется. Справочный вопрос не меняет параметры заявки; форма из вопроса используется только для поиска.
# Клиентский вход

PostgreSQL-кабинет требует клиентский логин. Созданы 30 синтетических учётных
записей с привязкой к одному бизнесу на клиента. Локальный список входов:
`../prom/prom_lab/ai_agents_lab/data/client_credentials.json` (исключён из Git).
Настройка входа, подготовка новых записей и очередь проверки сотрудника описаны
в [CLIENT_AUTH_AND_REVIEW.md](../../docs/CLIENT_AUTH_AND_REVIEW.md).
