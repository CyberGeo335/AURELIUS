# AURELIUS — веб-кабинет V2

Десктопный демонстрационный кредитный кабинет (от 1280 px). Все сведения синтетические; подпись и выдача имитируются.

## План реализации

1. Создать React + TypeScript + Vite, Tailwind, shadcn/ui, Motion и локальные шрифты Onest/Unbounded. Перенести токены V2, шапку и шевроны этапов.
2. Реализовать типизированные поля R01–R03 из CSV, аннуитет, статусы и интерфейс CreditApi. Единый MockCreditApi хранит заявки, ревизии, предложения, дозапросы и аудит в localStorage и синхронизирует вкладки.
3. Собрать демо-вход, главную клиента, пошаговую анкету, список/карточку заявки, решение, подпись и выдачу. Затем очередь банка, ручной разбор и журнал.
4. Подключить только существующий API помощника через отдельный HttpChatApi; основной сценарий автономен. Задокументировать будущую интеграцию модулей 3–5.
5. Проверить четыре сквозных сценария, доступность, reduced motion, калькулятор, переходы статусов и ключевые экраны. Выполнить build, test, lint и браузерную проверку.

## Дизайн

Источник истины — предоставленный DESIGN.md V2 и пять PNG-референсов. UI/UX Pro Max: проверена рекомендация Banking/Traditional Finance, используются доступность и ясная иерархия; предлагаемая библиотекой палитра уступает утверждённой V2. Apple Design: немедленный отклик на нажатие, прерываемые spring-переходы и reduced motion. Стеклянные поверхности и тени не добавляются: V2 задаёт непрозрачные панели без теней.

Новый код размещается только в personalCab/web; существующие модули не изменяются.

## Запуск

Нужен Node.js LTS (проверено с Node 24.20.0 и npm 11.19.0). Из `personalCab/web`:

```sh
npm ci
npm run dev
```

Открыть **http://127.0.0.1:5174/**. По умолчанию `VITE_API_MODE=mock`: Python, Ollama, база данных, внешние реестры и интернет во время работы приложения не нужны. Шрифты и зависимости собираются локально. Первый `npm ci` требует доступа к npm.

```sh
npm run build
npm run preview
npm run test
npm run lint
```

`preview` открывает производственную сборку на http://127.0.0.1:4173/. Не коммитить `node_modules/`, `dist/`, `.env` и результаты локальной проверки.

### Режим с существующим помощником

Скопировать `.env.example` в `.env`, установить `VITE_API_MODE=http` и перезапустить Vite. Из корня репозитория запустить уже существующий сервер:

```sh
python -m personalCab.frontend.server
```

Ему нужны зависимости существующего модуля 1 и Ollama с `gpt-oss:20b`; см. `../frontend/README.md`. Python слушает `127.0.0.1:5173`; Vite остаётся на **5174**, проксирует `/api`, меняет Host и Origin согласно проверкам сервера. При отсутствии сервера/модели помощник показывает понятное состояние, формы продолжают работать. Cookies должны быть разрешены. 428 повторяется один раз с тем же ID; при 409/503/транспортной ошибке пользователь повторяет исходное сообщение с прежним ID.

`http` включает живой **чат**, а кредитные экраны продолжают работать через MockCreditApi: HTTP-модулей 3–5 ещё нет. Серверная демо-личность чата управляется существующим сервером и не переключается новым демо-входом. Извлечённые суммы, сроки, форма и цель показываются в панели с указанием «Подтвердите в анкете», без автоматической выдачи согласий или изменения кредитной заявки.

### Docker

```sh
docker build -t aurelius-web .
docker run --rm -p 8080:80 aurelius-web
```

Многоэтапная сборка Node → nginx, SPA fallback для прямых ссылок. Контейнер обслуживает автономный mock-режим; `/api` явно возвращает 503. Общий compose и контейнерная интеграция чата не создавались. Dockerfile подготовлен; локальный контейнерный запуск не проверен: Docker CLI установлен, но Docker Engine выключен.

## Структура

```text
src/app/              маршруты, роли, провайдер CreditApi и обработка ошибок
src/pages/client/     главная, анкета, заявка/решение/подпись
src/pages/bank/       очередь, разбор и журнал
src/components/ui/    компоненты shadcn/ui, добавленные CLI и адаптированные под V2
src/components/v2/    панели, этапы, источники, графики, факторы и помощник
src/domain/           типы, поля, валидация, статусы, расчёты и синтетический риск
src/api/              интерфейс CreditApi, клиент существующего чата, карта интеграции
src/mocks/            синтетические профили и MockCreditApi
src/styles/           токены V2 и тема Tailwind
src/test/             доменные, API и компонентные проверки
data/                 исходные 99 требований и тестовая выписка
scripts/              воспроизводимая генерация конфигурации полей
```

Подробная карта методов на модули и таблицы — [src/api/README.md](src/api/README.md). Готовые HTTP-адреса модулей 3–5 не выдумываются.

Исходный CSV сохранён без ручного переписывания. Перегенерация:

```sh
python scripts/generate-fields.py
npx prettier --write src/domain/fields.ts
```

Кроме указанного стека используются `react-router` для прямых ссылок и маршрутов, `lucide-react` для единой SVG-иконографии, `radix-ui`, `class-variance-authority`, `clsx` и `tailwind-merge` как зависимости shadcn/ui. Дополнительных сервисов, платных API и внешних CDN нет. Версии закреплены `package-lock.json`; TypeScript работает с `strict: true`.

## Проверка четырёх демо-путей

Для чистого показа на входе нажать «Сбросить демо-данные» и подтвердить. Сброс затрагивает вкладки этого браузера. Отдельные вкладки можно оставить с разными ролями; localStorage общий, выбор роли — отдельный для каждой вкладки. Между разными браузерами данные не синхронизируются.

1. **ИП, одобрение.** Войти как ИП Карпов → «Новая заявка» у R01 → оставить 1 500 000 ₽ / 12 мес., обычную проверку и демонстрационный ИНН → «Дальше». Проверить реквизиты и раскрыть контакты/полномочия, подтвердить «Всё верно», взять демо-выписку и подтвердить лизинг. На шаге согласий отдельно отметить БКИ, обработку данных и корректность анкеты → отправить. Примерно за 10 секунд этапы доходят до предложения. Платёж: 142 494 ₽, переплата 209 922 ₽. Другой срок создаёт новую ревизию и перепроверку; старые условия нельзя принять. Принять актуальное предложение → подтвердить условия → «Подписать · DEMO» → «Имитировать выдачу» → «Деньги на счёте».
2. **Не хватает данных.** Создать новую R01 и выбрать демо-сценарий «Не хватает выписки». Заполнить/подтвердить ту же анкету → отправить → получить дозапрос конкретной выписки. В карточке добавить `data/demo-statement.csv` и ответ → «Отправить данные». Номер заявки сохраняется, ревизия увеличивается, история дозапроса остаётся; проверка завершается предложением. Для сбоя источника вместо этого выбрать «Внешний источник недоступен»: появится ожидание и автоматический повтор примерно через 8 секунд, без кредитного отказа.
3. **ООО, встречное предложение.** В клиентской вкладке войти как ООО «Зерно Опт» и открыть исходную `R01-2026-00151`. В банковской вкладке открыть ту же заявку из очереди. Проверить `DSCR_BELOW_MIN`, конфликт выручки, PD 4,8%, покрытие 1,26×; варианты А 2,2 млн / 18 мес. → 1,59× и Б 3 млн / 24 мес. → 1,50×. Выбрать А/Б/оба, написать содержательное обоснование от 15 символов → сохранить. Клиент без перезагрузки получает встречное предложение и принимает один вариант. Решение и принятие появляются в общем журнале.
4. **Отказ.** В новой заявке ИП выбрать демо-сценарий «Отказ: действующая просрочка», пройти анкету и отправить. Клиент получает понятную причину и следующий возможный шаг. Сотрудник открывает эту заявку и видит код `ACTIVE_OVERDUE_90` и основание. Дополнительно у любой заявки на ручном разборе можно выбрать «Отказать» с обязательным обоснованием: код `MANUAL_POLICY_DECLINE`. Дозапрос сотрудника также требует обоснования и возвращает заявку клиенту.

Исходная заявка ИП `R01-2026-00142` уже содержит дозапрос по лизингу, поэтому его можно показать сразу, без создания новой анкеты.

## Проверки и ограничения

Автотесты проверяют аннуитет и погашение основного долга, форматы полей, допустимые статусы, четыре ветви мока, срок/ревизию предложения, отсутствие дублей, синхронизацию хранилища, ключевые экраны, обязательное обоснование и ответы API помощника 428/400/409/503. Во время разработки проверяются `npm run build`, `npm run test`, `npm run lint` и сквозные сценарии в браузере.

Отличия от статичных PNG обоснованы рабочим сценарием:

- белый текст на красном увеличен до полужирного 18,67 px; мелкие элементы на красном используют контрастный тёмный текст;
- главная первоначально показывает реальный дозапрос, а не одновременно продолжающуюся проверку и блокирующий запрос;
- счётчики очереди считаются по шести исходным заявкам, а не по нарисованным 18; новые заявки немедленно учитываются;
- R02/R03 доступны для анкеты, хотя в референсе главной помечены «скоро»; на решении показаны их продуктовые поля;
- контакты, полномочия и полная анкета раскрываются отдельно, чтобы сохранить основную иерархию макета;
- на решении добавлены покрытие, полный график, история и источники; смена срока явно запускает новую проверку;
- на входе и в формах есть необходимые демо-контролы, которых нет в пяти статичных макетах.

Работа рассчитана на десктоп от 1280 px. Мобильная адаптация не выполняется. Полноценная авторизация, безопасная загрузка/анализ файлов, реальные реестры, скоринг, подпись и банковская выдача — за пределами демонстрационного фронтенда. Имя загруженного файла хранится локально, его содержимое не сохраняется и не отправляется. Для R02/R03 платёж — явно помеченный пример полного использования лимита с аннуитетом, а не готовый график линии/овердрафта. Риск не выводится из покрытия: показываются только синтетические оценки из V2, неизвестное остаётся неизвестным.
