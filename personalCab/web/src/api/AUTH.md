# Вход и сессия кабинета

Проверено по коду коммита `6a9a4c1` (ветка `chore/cleanup-legacy`).

В HTTP-режиме `HttpAuthApi` обращается к `cabinet_server`. Пользователь вводит логин и пароль; имя, фамилия, роль и компания приходят с сервера. Роль не назначается клиентским полем формы.

- `signIn` выполняет `POST /api/v2/login` и получает публичный профиль.
- `restore` читает `GET /api/v2/session` и восстанавливает профиль действующей сессии.
- `signOut` выполняет `POST /api/v2/logout`, очищает состояние кабинета и возвращает пользователя к входу.

Cookie — `aurelius_v3`, `HttpOnly`, `SameSite=Strict`, `Path=/api/v2`, срок 8 часов. Токен сессии хранится в БД как хэш. Пароль не входит в `AuthSession` и не сохраняется браузером приложения в localStorage/sessionStorage.

`Providers` связывает API с контекстом сессии и состоянием заявок. При выходе кредитный API очищает локальное состояние. Владение заявкой, роль и назначение сотрудника проверяются сервером на кредитных действиях.
