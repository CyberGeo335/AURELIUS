# Расширенная документация AURELIUS

AURELIUS связывает заполнение заявки, работу сотрудника, скоринг и принятие опубликованного предложения в одном сохраняемом процессе. Ценность реализации — единая заявка с происхождением сведений, подтверждаемое заполнение через ассистента и явная граница между расчётом риска и решением банка.

Исходный пакет подготовлен по `68b7b57c0e501e4575bc2a10eee20e6e42f529d4`. При переносе 26.10.2026 он согласован с `main` / `138b799bb8fee4ed5990e8d0f04c45aeb81d56b6`, включающим c549a06 и новые основные документы. Рабочий контур: React/TypeScript, Python `/api/v2`, PostgreSQL 17, scoring/main, Agent V2, Ollama gpt-oss:20b. Исходные протоколы и результаты интеграционной сверки имеют отдельные версии: [VALIDATION](VALIDATION.md).

## Как читать доказательства

Реализация установлена по исходникам и артефактам указанного коммита. [Модель](scoring-model.md) имеет синтетические validation/test-отчёты; они не измеряют качество реального портфеля. [AUR-01–10](../technical/testing/LLM_SCENARIOS_01_10_RESULTS.json) — опубликованный протокол, а не повторный запуск при написании документов. Пилотные гипотезы и предлагаемые пороги находятся отдельно в roadmap.

В заявке реализованы R01–R03; справочный каталог содержит 16 направлений. Положительный путь заканчивается ACCEPTED. Документы сохраняются без автоматического извлечения финансов. Эти границы подробно объяснены в соответствующих контрактах.

Внешние обращения и недоступные локальные источники перечислены в [research](research.md) и [реестре исходных материалов](research-raw/README.md). Полный список сверенных источников и результаты структурной проверки — [VALIDATION](VALIDATION.md). [PROGRESS](PROGRESS.md) предназначен для продолжения работы и фиксирует состояние каждого файла.
