# Дизайн: процесс и его состояние

Документ подготовлен по коду main 26.10.2026. Он не выдаётся за ранее существовавший в main локальный DESIGN.md. Источник токенов — [styles/index.css](../../../personalCab/web/src/styles/index.css), композиции — [App](../../../personalCab/web/src/app/App.tsx), [business](../../../personalCab/web/src/business/) и pages.

## Информационная архитектура

| Роль / маршрут | Основное содержание | Основное действие |
|---|---|---|
| `/` | вход и ошибка авторизации | войти |
| `/client` | компания, заявки, следующий шаг | открыть/создать заявку |
| `/client/applications` | список обращений и статусы | продолжить нужное обращение |
| `/client/new/:id` | этапы анкеты, требования, подтверждения | сохранить / отправить |
| `/client/applications/:id` | статус, дозапросы, документы, опубликованные условия | ответить / принять |
| `/client/products` | продуктовые карточки и выбор | создать R01–R03 |
| `/client/documents` | документы видимых заявок | открыть документ |
| `/client/company` | профиль компании | чтение исходных сведений |
| `/bank`, `/bank/mine` | общая очередь / собственные назначения | взять в работу / открыть |
| `/bank/applications/:id` | оценка, проверки, документы и решение | verify / score / review |
| `/bank/clients` | компании и связанные заявки | открыть заявку |
| `/bank/policies` | сводка DEMO-политики в HTTP-режиме | чтение, без редактора |
| `/bank/journal` | журнал | проследить действия |

Ассистент — панель, связанная с выбранной заявкой; это не самостоятельный канал принятия финансового решения. Предложенные поля отображаются отдельно от сохранённой формы.

## Визуальная система

| Токен | Значение | Назначение |
|---|---|---|
| brand | #ef3124 | основное действие |
| canvas / surface | #f2f3f5 / #ffffff | фон / карточка |
| ink | #121213 | основной текст |
| assistant | #7a63f1 | маркировка ассистента |
| positive / attention | #0b7a2e / #9a5200 | результат / требуемое внимание |
| info | #0f5fb8 | информация и focus ring |
| font-sans / font-display | Onest / Unbounded, system-ui fallback | текст / акцент |
| radius-field / card / hero | 1rem / 1.75rem / 2rem | согласованная геометрия |

Статус передаётся текстом и контекстом действия, а не только цветом. `Card`, `Action`, `EmptyState`, `ErrorState` в [primitives](../../../personalCab/web/src/components/v2/primitives.tsx) задают повторяемые оболочки. Формы и HTTP-экраны используют доменные преобразования, чтобы не показывать клиенту внутренние расчётные коды как обещание банка.

## Состояния и ошибки

- Восстановление входа и lazy-loading страницы сопровождаются role=status.
- Пустая очередь/список оформляются отдельным EmptyState; ошибка загрузки — ErrorState, действие можно повторить.
- Во время action.busy соответствующие действия блокируются; результат подтверждается новым state, а не только локальным кликом.
- Просроченная версия требует перечитать заявку. Недоступность модели предлагает повтор или заполнение формы. OFFER_STALE показывает возврат на проверку.
- ErrorBoundary предлагает обновить страницу. В его тексте остаётся формулировка о хранении демо-заявок «в браузере»; для HTTP источником истины является PostgreSQL. Это выявленное несоответствие сообщения, код в документационной задаче не менялся.

## Адаптивность и доступность

Текущий body имеет min-width:1260px. Есть media queries для отдельных блоков, но они не доказывают полноценную мобильную компоновку; банковская таблица имеет собственный min-width:1120px. Основной сценарий рассчитан на desktop. Проверка на узком экране и переработка таблицы — требования развития.

В коде есть skip-link к main, управление фокусом после смены маршрута, aria-label навигации и кнопок, role=status, правила prefers-reduced-motion и prefers-contrast. Наличие этих механизмов не означает сертификацию WCAG. Клавиатурный путь, zoom 200%, контраст и экранный диктор должны быть проверены на живом стенде по [критериям](FRONTEND-REQUIREMENTS.md).
