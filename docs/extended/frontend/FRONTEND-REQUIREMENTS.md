# Требования к интерфейсу и приёмка

Источник — текущие маршруты, HTTP-адаптеры и тесты. Статус «код» означает наличие реализации, «план» — предлагаемый критерий. Проверка в браузере при подготовке этого комплекта не выполнялась.

| ID | Роль / экран | Требование | Критерий | Статус / свидетельство |
|---|---|---|---|---|
| UI01 | вход | восстанавливать серверную сессию | 401 возвращает форму входа, роль берётся из session | код: HttpAuthApi, auth.test.tsx |
| UI02 | обе роли | открывать свой layout | попытка открыть чужую роль перенаправляется; сервер сохраняет контроль доступа | код: App.tsx |
| UI03 | клиент / продукт | R01–R03 создают реальные заявки | создание возвращает application_id, список после refresh содержит заявку | код: client_home.test.tsx |
| UI04 | клиент / форма | показывать требования продукта и ИП/юрлица | обязательность и формат соответствуют requirements БД | код: http_form_steps.test.tsx |
| UI05 | клиент / форма | сохранять черновик без потери версии | после save и повторного чтения значения прежние; 409 не затирает изменения | код: HttpCreditApi, http_form_steps.test.tsx |
| UI06 | клиент / ассистент | показывать предложение до записи | чат не меняет форму; подтверждение обновляет поля и снимает pending | код: http_assistant.test.tsx |
| UI07 | клиент / подача | согласия и корректность анкеты отдельны | без трёх подтверждений сервер отклоняет подачу | код: cabinet.validate_submission |
| UI08 | обе роли / документы | показывать состояние файла и связь с запросом | PDF/CSV скачивается авторизованно; upload не закрывает запрос | код: http_credit.test.tsx, cabinet_documents |
| UI09 | сотрудник / очередь | разделять общую очередь и мои назначения | claim назначает одного; score/review другого отклоняются | код: http_queue.test.tsx |
| UI10 | сотрудник / рассмотрение | различать рекомендацию и решение | видны PD/лимит и причины; review требует причину и актуальный расчёт | код: http_credit.test.tsx |
| UI11 | клиент / результат | скрывать внутренний расчёт | API assessment=null; видны опубликованные сумма/срок/ставка | код: server_stage.test.ts |
| UI12 | клиент / причины | показывать сообщения сотрудника | API оставляет только точные BANK_APPROVE/BANK_REJECT/BANK_REQUEST_DATA, интерфейс представляет эти сообщения | код: Cabinet.project, clientReasons.ts; исправление c549a06 включено |
| UI13 | обе роли / ошибка | восстанавливать состояние после отказа | после 5xx адаптер пытается refresh, не рисует кредитный отказ | код: HttpCreditApi.command |
| UI14 | клиент / принятие | обрабатывать снятие устаревшего оффера | OFFER_STALE приводит к чтению реального состояния и возврату на рассмотрение | код: http_credit.test.tsx |
| UI15 | desktop | сохранять читаемость исходной компоновки | проверить браузер при ширине ≥1260px и длинных русских данных | код CSS; визуальная приёмка ожидается |
| UI16 | клавиатура | полный основной путь без мыши | вход → форма → подтверждение → результат; видимый фокус и возврат из панели | план живой проверки |
| UI17 | доступность | zoom и диктор | при 200% нет потери действия, labels/ошибки озвучиваются | план проверки; не заявлен WCAG-аудит |
| UI18 | узкий экран | мобильная компоновка | согласованный breakpoint, таблицы доступны без потери содержания | план; body min-width пока 1260px |

Пути перечисленных тестов — [src/test](../../../personalCab/web/src/test/), код экранов — [App](../../../personalCab/web/src/app/App.tsx), интеграция — [backend](../backend-integration.md). Приоритеты пилота согласуются отдельно; каталог продуктовых требований — [requirements](../requirements.md).
