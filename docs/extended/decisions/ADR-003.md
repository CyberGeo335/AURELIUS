# ADR-003: Политика скоринга не меняется

Статус: действует в срезе `68b7b57c0e501e4575bc2a10eee20e6e42f529d4`. Дата принятия и автор ADR отдельно не установлены; развёрнуто 26.10.2026 из решения **Р3**. Это дата документирования, не дата решения команды.

## Контекст и принятое решение

Ниже исходная запись Р3, сохранённая по смыслу и формулировкам; относительные ссылки заменены навигацией к источнику.

- **Контекст.** Политика и модель подготовлены ML-частью команды (`scoring/main`). Кабинет и Docker-запуск подключают их как есть.
- **Решение.** Используются без изменений:
  - метод `annual_pd_limit` из `policy.demo.json`, версия `DEMO_ANNUAL_PD_V2`, минимальное покрытие (DSCR) 1,20;
  - экономические параметры `AURELIUS_MVP_20261024_V1` из `risk_policy_parameters`: спред 1,5 п.п., расходы 2 п.п., маржа 3 п.п., LGD 45%;
  - ключевая ставка 14% из `macro_indicators`.
- **Почему.** Решение владельца продукта. Параметры и их источники задокументированы в BASELINE.md.
- **Последствия.**
  - Все значения — допущения демо, а не нормативы банка.
  - Политика в БД действует по 17.12.2026.
  - Результат скоринга на исходных синтетических данных определяется самими данными (см. «Ограничения»).

## Аргументы

Неизменность модели и политики позволяет проверять интеграцию при постоянных финансовых предпосылках.

## Альтернативы и компромисс

Редакционный анализ при подготовке расширенной документации, не протокол исторического обсуждения команды: Перенастроить пороги под демонстрационный набор позволило бы изменить распределение исходов, но лишило бы сравнение с исходной политикой смысла.
