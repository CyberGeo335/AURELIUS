# ADR-009: Демо-учётки и сессии

Статус: действует в срезе `68b7b57c0e501e4575bc2a10eee20e6e42f529d4`. Дата принятия и автор ADR отдельно не установлены; развёрнуто 26.10.2026 из решения **Р9**. Это дата документирования, не дата решения команды.

## Контекст и принятое решение

Ниже исходная запись Р9, сохранённая по смыслу и формулировкам; относительные ссылки заменены навигацией к источнику.

- **Контекст.** 32 синтетические учётные записи хранятся в `public.user_accounts`; роль и компания определяются сервером.
- **Решение.** Сессионный токен хранится как хэш; cookie имеет `HttpOnly`, `SameSite=Strict`, `Path=/api/v2`, срок 8 часов. POST проверяется по `Origin`. Пароль не возвращается в API и не пишется в логи.
- **Последствия.** Для демонстрации учётки получают из запущенной БД по инструкции 09.

## Аргументы

Серверная сессия связывает действия с ролью и компанией независимо от пользовательских полей запроса.

## Альтернативы и компромисс

Редакционный анализ при подготовке расширенной документации, не протокол исторического обсуждения команды: Промышленный IdP даёт управляемую идентификацию, но требует отдельной интеграции; демонстрационные пароли не следует переносить в production.
