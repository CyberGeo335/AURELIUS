# ADR-002: Скоринг читает финансовые данные только из БД банка

Статус: действует в срезе `68b7b57c0e501e4575bc2a10eee20e6e42f529d4`. Дата принятия и автор ADR отдельно не установлены; развёрнуто 26.10.2026 из решения **Р2**. Это дата документирования, не дата решения команды.

## Контекст и принятое решение

Ниже исходная запись Р2, сохранённая по смыслу и формулировкам; относительные ссылки заменены навигацией к источнику.

- **Контекст.** В браузере клиент может ввести любые числа.
- **Решение.** Кабинет вызывает `run_application(application_id, save=True)`. Все финансовые входы библиотека читает из БД сама, произвольный контекст из браузера не принимается.
- **Почему.** Риск оценивается по данным банка, а не по заявлению клиента. Анкета клиента сохраняется как `CLIENT` / `UNVERIFIED`.
- **Последствия.** Изменение анкеты не делает сведения клиента проверенными и не меняет записи `companies`. Если в БД не хватает финансовой истории, расчёт возвращает ручную проверку без PD (Р8).

В режиме DEMO отсутствующие ОКВЭД и дата регистрации могут читаться из подтверждённой анкеты конкретной заявки (`application_facts.py`). Они остаются `UNVERIFIED`, не изменяют `companies` и сохраняются в снимке с происхождением. Независимая проверка сотрудником — отдельное действие.

## Аргументы

Серверный источник финансовых входов отделяет заявление клиента от наблюдаемой банковской истории.

## Альтернативы и компромисс

Редакционный анализ при подготовке расширенной документации, не протокол исторического обсуждения команды: Доверять финансовым числам браузера проще для формы, но это не даёт банковского источника риска.
