# ADR-006: Клиенту показываются только причины сотрудника

Статус: действует; уточнено по `main` / `138b799`, включающему серверное исправление c549a06. Дата принятия и автор ADR отдельно не установлены; развёрнуто 26.10.2026 из решения **Р6**. Это дата документирования, не дата решения команды.

## Контекст и принятое решение

Запись Р6 актуализирована по объединённой реализации; история включённого изменения — в [протоколе согласования](../../technical/testing/BRANCH_ALIGNMENT_C549A06.md).

- **Контекст.** У скоринга свои коды причин (например, `BANK_CONFIRMATION_REQUIRED`, `MVP_INPUTS_CONFIRMATION`, `DB_INPUTS_UNAVAILABLE`). Они описывают внутреннюю проверку, а не ответ клиенту.
- **Решение.** Серверный `Cabinet.project` передаёт клиенту только точные `BANK_APPROVE`, `BANK_REJECT`, `BANK_REQUEST_DATA`, то есть текст сотрудника. Интерфейс (`src/domain/clientReasons.ts`) представляет эти сообщения; внутренние причины сохраняются в представлении сотрудника.
- **Почему.** Клиенту показывается понятное сообщение о результате рассмотрения.
- **Последствия.** Интерфейс использует сообщения сотрудника для объяснения результата клиенту.

## Аргументы

Текст сотрудника объясняет результат клиенту в терминах рассмотрения заявки; серверная проекция ограничивает состав данных до передачи в браузер.

## Альтернативы и компромисс

Редакционный анализ, не протокол исторического обсуждения команды: отбор только в интерфейсе оставлял бы внутренние причины доступными через API. Принятый в c549a06 серверный allowlist переносит границу в проекцию роли. Проверяется точное совпадение кода, а не любой префикс BANK_*.
