# 00. Путеводитель для жюри

Проверено по коду коммита `6a9a4c1` (ветка `chore/cleanup-legacy`).

AURELIUS объединяет клиентский веб-кабинет, обработку заявки сотрудником, скоринг и ассистента в одном кредитном процессе. Текущий контур: кабинет v3, PostgreSQL с дампом v4, `scoring/main`, Agent V2 и Ollama `gpt-oss:20b`.

## 1. Начать проверку

1. [Запустите решение](../README.md#запуск) и откройте `http://127.0.0.1:5173`.
2. [Получите синтетические учётки](../README.md#тестовые-учётные-записи) клиента и сотрудника.
3. Пройдите [сценарий проверки](../README.md#сценарий-проверки) или [подробные демо-пути](03-demo-scenarios.md#1-клиент-оформляет-и-отправляет-заявку).
4. Состав тестов и опубликованные протоколы — [08](08-testing.md#1-что-тестируется).

## 2. Версия и состав

Код: `6a9a4c15a0c0eee4c74a62a1e15b9e5bb704eaf6`, ветка `chore/cleanup-legacy`. Эта редакция документов сверена по этому коду и манифесту дампа v4. У каждого протокола проверки собственные условия и объём; [08](08-testing.md#2-протоколы-проверок) отделяет результаты от инвентаря тестов. Итоговый полный hash сдаваемого репозитория определяется командой `git rev-parse HEAD`; [README: версия](../README.md#версия).

Исходные требования: [ABOUT.md](case/ABOUT.md#постановка-задачи), [технические требования](case/ABOUT.md#технические-требования-к-решению-и-формат-сдачи) и [ограничения](case/ABOUT.md#ограничения). Ниже статус относится к реализации и артефактам прототипа, а не к результату каждого отдельного тестового запуска.
