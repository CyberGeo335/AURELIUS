# 00. Путеводитель для жюри

Проверено на коммите `40b8038` (ветка `test-dev`).

AURELIUS — прототип кредитного кабинета малого и микробизнеса: клиент и сотрудник работают с одной заявкой в PostgreSQL. Проверяемый контур — кабинет v3 (`cabinet_server.py` и `cabinet*.py`), фронт `personalCab/web` в HTTP-режиме, скоринг `scoring/main`, Agent V2 ассистента и локальная модель `gpt-oss:20b` через Ollama.

## 1. Начать проверку

1. Запустите решение по [README: запуск за 5 минут](../README.md#запуск-за-5-минут). Подробные требования, переменные и диагностика — [09, разделы 1–5](09-deployment.md#1-требования-к-окружению).
2. Откройте `http://127.0.0.1:5173`, получите синтетические учётки из БД по [инструкции](../README.md#тестовые-учётные-записи). По HTTP на другом компьютере действия интерфейса не работают: [ограничение и обход через SSH](09-deployment.md#8-доступ-с-других-компьютеров).
3. Пройдите [семь шагов проверки](../README.md#сценарий-проверки): заявка → рассмотрение → дозапрос → ответ с документом → отказ с причиной. [Шесть демо-путей и 24 скриншота](03-demo-scenarios.md#1-клиент-оформляет-и-отправляет-заявку) показывают тот же процесс, ассистента и отмену.
4. Сопоставьте результат с [прогонами тестов](08-testing.md#2-результаты-прогонов) и [ограничениями демо](02-decisions.md#ограничения-текущей-версии).

**Ожидаемый результат на исходном дампе:** скоринг возвращает `MANUAL_REVIEW` / `DB_INPUTS_UNAVAILABLE`, без PD и предложения. В дампе 12 месяцев выручки, расчёту нужно 13 завершённых. Поэтому основной демонстрационный путь завершается отказом сотрудника с причиной; положительный путь на исходном дампе недоступен. В коде есть одобрение и принятие предложения, но их интеграционная проверка требует отдельной БД: [08, раздел 2.2](08-testing.md#22-пропущенные-python-тесты). Подписание и выдача не реализованы.
