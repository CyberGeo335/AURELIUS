# Версионирование снимков PostgreSQL

По требованию владельца проекта после каждого изменения **рабочей** БД:

1. Сделать следующий полный дамп структуры и содержимого в `bd/v_N (actual)`.
2. Сохранить отдельно schema-only SQL; записать SHA256 и числа строк в manifest.
3. Проверить архив через pg_restore; перед сменой actual желательно полное
   восстановление в отдельную тестовую БД и сверка всех таблиц.
4. После успешной проверки убрать `(actual)` у предыдущей версии. Старые версии
   не удалять и не перезаписывать. Актуальной может быть только одна папка.

Это относится и к изменениям начальных параметров/справочников, не только DDL.
Дамп должен включать данные аккаунтов, как существующие business_scoring_wauth.backup.
Тестовые временные базы не являются новой версией рабочей БД.

Текущая актуальная версия — `v_4 (actual)`: добавлена синтетическая выручка
за сентябрь и октябрь 2025 года всем 30 DEMO-компаниям (60 операций; всего
780 строк в bank_transactions). Предыдущий снимок сохранён в `v_3`.
Историческая `v_2` — до заполнения макроиндикатора и риск-политики. Числовые настройки MVP сопровождаются источниками
и явными допущениями в `main/decision_engine/BASELINE.md`.
