# Исправления LLM-сценариев AUR-01–10

Дата проверки: 26.10.2026. Исходная проблема воспроизведена по пользовательскому
отчёту полного заполнения десяти сценариев.

## Причины и изменения

- Извлечение и типизированный запрос не поддерживали восемь из девяти реквизитов.
  Добавлены company_name, ogrn, ogrnip, legal_address, director_name, okved_main,
  registration_date и actual_activity_description; inn уже поддерживался.
  Каждое поле требует точной цитаты текущего сообщения и независимой проверки.
  Явные помеченные реквизиты и однозначные числовые сумма/срок восстанавливаются
  при пропуске моделью, затем проходят ту же проверку. Это не поиск в реестре.
  Возраст не извлекается вычислением из даты; срок транша не становится сроком договора.
- Форма бизнеса ошибочно читалась и сохранялась в R01_12 (наименование).
  Поля компании теперь сопоставляются с target_db_field действующего каталога
  с учётом типа заёмщика. Подтверждение ООО заполняет R01_14 и не затирает имя.
- На каждом ходе диалог восстанавливает сохранённые реквизиты анкеты.
  Пустой ИНН в companies больше не затирает пользовательский ответ даже при
  VERIFIED у профиля. Известные сумма, срок, ИНН и правовая форма не теряются
  между сообщениями. Неверные ответы не заменяют правильные соседние значения.
  Явно очищенное поле формы сбрасывает устаревшее значение диалога; помощник
  указывает следующий отсутствующий поддерживаемый реквизит из каталога.
- Отсутствующие в companies ОКВЭД и дата регистрации доступны DEMO-расчёту
  из подтверждённой анкеты конкретной заявки. Проверяются формат, дата
  доступности и подтверждение подачи. Источник/идентификаторы/UNVERIFIED
  сохраняются в снимке и аудите. Конфликт с профилем требует сотрудника.
  Production не использует этот путь, companies не обновляется и проверка
  сотрудником не подменяется. Контракт описан в ../scoring/INTEGRATION.md.
- Причина отсутствия 13 завершённых месяцев устранена предыдущим дополнением
  синтетической истории в v4. Нули и выдуманные финансовые признаки не добавляются.

## Повтор пользовательских сценариев

Использована отдельная копия полного v4, настоящий HTTP-обработчик кабинета,
локальная Ollama gpt-oss:20b и настоящий зарегистрированный CatBoost.
Пароли использовались только в памяти, в отчёт не попадали.
Браузерная проверка отображения предложений выполнена отдельно на тестовых данных.

Для каждого клиента через HTTP созданы новая R01-заявка и исходная анкета
с намеренно пропущенным реквизитом. Затем переданы исходные сообщения отчёта
и явно подтверждены предложения. Недостающий реквизит **не добавлялся формой**.
После диалога явно подтверждены согласия и корректность анкеты, выполнена подача.

| AUR-01 | ИНН | Сохранён чатом; расчёт выполнен |
| AUR-02 | Наименование | Сохранено чатом; расчёт выполнен |
| AUR-03 | ОГРН | Сохранён чатом; расчёт выполнен |

| AUR-10 | Все сведения известны | Подача и расчёт выполнены |

Все десять сценариев завершились без DB_INPUTS_UNAVAILABLE, с результатом
MANUAL_REVIEW / ELIGIBLE. Это результат DEMO-расчёта, а не одобрение кредита.
Девять ответов сохранены как CLIENT / UNVERIFIED, все строки companies
остались неизменными. Временная тестовая БД удалена, рабочая БД не менялась.
Подробные результаты: [LLM_SCENARIOS_01_10_RESULTS.json](LLM_SCENARIOS_01_10_RESULTS.json).

Для существующего стенда с v3 нужен явный запуск
`scoring/bd/seeds/backfill_revenue_2025_09_10.sql`; смена backup в Compose
сама по себе не обновляет существующий том. Новый том получает v4.

## Регрессионные проверки

Итог: 125 проверок V2 и библиотеки скоринга на изолированной PostgreSQL,
15 проверок прежнего общего слоя и 16 проверок интерфейса прошли.
ESLint изменённых файлов, TypeScript/Vite HTTP-сборка и git diff --check прошли.

  независимая проверка, сохранение соседних полей, запрет усечения ОГРН,
  неверные и будущие даты, разделение срока транша и договора.

  правильный маппинг правовой формы, синхронизация известных данных,
  UNVERIFIED и неизменность companies.

  происхождение, конфликт, ограничение DEMO, изоляция по заявке,
  дата доступности и отсутствие подтверждения.
- `personalCab/web/src/test/http_assistant.test.tsx`: подписи новых реквизитов,
  цитаты и отсутствие записи предложения до подтверждения.
